# AI 会话知识库维护流程

## 1 目的

本流程用于把一次 AI 工作会话中已确认的结论、决策和治理口径沉淀为知识库 SOP。本文件放在项目根目录 `.sop/`，作为本次会话的可复用记录。

## 2 适用范围

适用于以下会话场景：

- 调整了知识库治理规则，例如编号、类型、签批、发布语义。
- 对现有 SOP 做了重新定性或内容收敛。
- 修正了工具链契约，例如 registry、发布清单、校验规则。
- 其他适合固化为操作程序的结论。

不适用于临时排障、一次性文件整理和尚未确认的讨论。

## 3 输入

- 本次会话的决策清单：用户明确要求、已确认结论、已删除的旧语义。
- 当前仓库状态：`sops/registry.json`、`sops/REGISTRY.md`、相关 md 与 `tools/`。

## 4 流程

### 4.1 确认用户意图

先区分两类请求：

- “写 SOP 进 `.sop/`”表示在项目根目录的 `.sop/` 下新建会话 SOP，不迁移现有 `sops/`。
- “把目录改成 `.sop/`”才表示迁移知识库源目录。

若请求可能影响现有目录和发布链，先确认，再执行。

### 4.2 起草 SOP 内容

按以下结构起草：

| 章节 | 内容 |
| --- | --- |
| 目的 | 为什么需要这份 SOP |
| 适用范围 | 什么场景适用 |
| 输入 | 启动前需要什么 |
| 流程 | 可执行步骤 |
| 检查 | 完成条件 |
| 本次会话固化记录 | 已确认的结论 |

正文使用 procedure 风格，步骤明确，不写口语化建议。

### 4.3 放置文件

- 新建文件放入项目根目录 `.sop/`。
- 文件名使用清晰的会话主题，例如 `AI会话知识库维护流程.md`。
- 现有知识库源目录 `sops/` 保持不动。

### 4.4 登记文档

本文件默认作为会话沉淀文件放在 `.sop/`。若后续需要正式纳入发布链，再按现有主登记表 `sops/registry.json` 登记，并将 `source` 写为 `.sop/<文件名>.md`；不要新建第二套 registry。

### 4.5 验证

若没有改动现有工具链和 `sops/`，只新增 `.sop/` 文件，运行：

```bash
python tools/kb.py check
```

若后续登记并修改了发布链，再运行：

```bash
python tools/kb.py test
python tools/kb.py publish --dry-run
```

## 5 检查

- [ ] 现有 `sops/` 未被移动或改名
- [ ] 会话 SOP 位于根目录 `.sop/`
- [ ] 未新增与现有主登记表冲突的 registry
- [ ] 若改动工具链，check / test / publish dry-run 均通过
- [ ] 若发布链路径改变，已同步 token 和 CI secret

## 6 本次会话固化记录

| 决策 | 结论 |
| --- | --- |
| DESK-001 | 重新定性为 procedure，标题改为作业程序 |
| DESK-002 | 重新定性为 reference，支撑资料清单 |
| IMS L1/L2/L3 | 不强制登记，文档性质由 doc_type 区分 |
| ISO 新版 | 新版发布前不提及，只写现行版本 |
| 签批信息 | 全手工维护，工具链不自动填写 |
| 退役文档 | 从 registry 删除，不保留 Retired 状态 |
| 源目录 | 维持 `sops/`，会话 SOP 放根目录 `.sop/` |
