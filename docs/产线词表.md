# 产线词表

> 本文档定义 SOP 文档产出线统一口径。事实来源为 `sops/registry.json`、源文件 front matter、发布日志（`%TEMP%` 发布快照 + 用户级持久日志 + CI artifact）。

## 核心词

| 词 | 定义 | 判定 |
| --- | --- | --- |
| 产线 | 从需求/变更到产出发布的统一链路 | 当前只有 1 条：SOP 文档产出线 |
| 在产 | 当前 registry 活跃条目 | 存在于 `sops/registry.json` 且源文件存在 |
| 待签批 | 文档尚未指定批准人 | `status=Draft` 且 `approver` 为空或为“待定” |
| 待审 | 文档已有批准人但尚未签批 | `status=Draft` 且 `approver` 已填且非“待定” |
| 已签批 | 文档已批准 | `status=Approved` |
| 已发布 | 存在成功发布记录或 registry 最近发布时间 | `publish-log.jsonl` 有该 `source` 的 `result=success`，或 `last_published_at` 非空 |
| 阻塞 | 产线无法继续推进 | 源文件缺失、token 缺失，或最新发布记录结果为失败 |
| 最近发布 | 该文档最近一次成功发布时间 | 优先取发布日志最大 `time`，缺失时取 registry `last_published_at` |
| 发布记录 | 每次真实成功上传飞书产生一条记录 | 同时写 `%TEMP%` 发布快照与用户级持久日志；CI 另上传 `publish-log` artifact |

## 边界

- 产线数按“链路”统计，不按文档数统计；当前 `产线数=1`。
- `Draft` 可发布，但不代表已签批；`Approved` 才是已签批状态。
- `--dry-run` 不产生发布记录。
- 发布日志不提交 git；报告中不输出 token 等敏感字段。
- 可选事实字段：`requirement_ref / approver / effective_date / reviewer / reviewed_at / approved_at / last_published_at`。
- 旧 registry 条目缺可选字段视为“未知”，不报错。
- 新文档缺 token 由 `token-bootstrap` 自动首次上传并登记，不再要求人工补映射。

## 验收一条线

本轮以 `SOP-GEN-2026-004` 冲通完整产线，并补上事实、自举与观测接线：

1. `python tools/kb.py check`
2. `python tools/kb.py test`
3. `python tools/kb.py publish --dry-run`（完整清单通过）
4. `python tools/kb.py publish .sop/AI会话知识库维护流程.md`（真实同名覆盖，写入发布日志并回写 registry）
5. `python tools/kb.py line --doc SOP-GEN-2026-004`（阶段显示已发布）
6. `python tools/kb.py fact link/review/signoff/sync`（事实登记入口）
7. `python tools/kb.py token-bootstrap --source <md>`（新文档首次上传自举）

边界：`.publish-tokens` 为 gitignore 本地配置，不入库；发布日志写 `%TEMP%` 与用户级持久目录，不提交 git。本轮为补齐缺口执行了真实飞书首次上传并登记 file token。
