# 表格排版规范

## 1 适用场景

本规范适用于本知识库**所有文档**（SOP、程序、系统说明、规范）中的表格排版，是表格格式的**唯一权威依据**。所有表格问题对照本规范自查，不再逐案查证。本规范由多轮权威查证收敛而成，每条规则均有出处（见 7 关联资料）。

## 2 北极星原则

**一句话：让读者以最少眼动，沿列垂直扫描，准确读取。**

核心机制：**一列 = 一条眼睛的垂直轨道**——列内所有单元格（含表头）对齐一致，形成一条直线；对齐方式由该列的内容类型决定。读者沿列直扫、跨行横读，全程不需要重新定位视线。

任何表格排版决策，都可以追问一句："这条规则是在服务这条垂直扫描线吗？"——是，则对；不是，则再想。

## 3 两种流派与选择

表格用途决定排版流派，两种流派存在真实分歧（这是查证确认的事实，不是缺陷）：

| | 流派 A · 数据报表 | 流派 B · 受控文档 |
| --- | --- | --- |
| 权威 | Stephen Few《Show Me the Numbers》 | 微软官方 / W3C / 企业 SOP 规范 |
| 典型场景 | 统计、绩效、财务数值表 | SOP、表单、受控文件 |
| 表头 | 与列数据同对齐（不居中） | 居中 + 加粗 + 单行 |
| 数值 | 右对齐（个位垂直） | 右对齐 |
| 日期 | 左对齐（同位数格式） | 居中 |
| 短标签 | 居中（同长度时） | 居中 |
| 行高 | 约 2 × 字号 | 自动适应内容 |

**本知识库全部采用流派 B**（SOP 为文字为主的受控文档）。若将来出现数据报表类文档（如指标统计表），单独按流派 A 处理。

## 4 四条共识

无论哪种流派，以下四条放之四海皆准：

1. **列内对齐统一**：一列一条扫描线，绝不混排（列级对齐，非格级）。
2. **表头永远可见**：跨页重复表头、防断行、文字简洁单行。
3. **内容类型驱动**：数值右对齐、文本左对齐、短标签/日期/版本居中。
4. **全文一致**：同宽、同边距、同底纹、同字号，文档内表格统一。

## 5 表格规范细则

### 5.1 对齐

| 位置 | 规则 | 依据 |
| --- | --- | --- |
| 表头行（第一行） | 水平居中 + 垂直居中 + 加粗 + 浅灰底纹（E6E6E6） | W3C th 默认居中加粗；企业模板"表头居中" |
| 行标签列（第一列） | 居中 | W3C th scope="row" 默认居中 |
| 日期 / 版本号 / 序号 | 居中 | 修订记录表"表格内文字居中"（文思海辉/renrendoc） |
| 短标签（人名、状态，≤8 字符） | 居中 | 表格排版"短标签居中"惯例 |
| 可运算数值（金额、数量） | 右对齐 | 数值右对齐是数据表格金科玉律 |
| 长文本描述 | 左对齐 | W3C td 默认左对齐 |
| 所有单元格垂直方向 | 居中 | 微软官方 Center 选项 + 行业通行 |

**列级统一**：同一列内的所有数据单元格对齐方式必须一致（对齐是列属性，不是格属性）。

### 5.2 数据表列宽

- 所有表格**铺满页宽**（AutoFit Window，100% 页面宽）——多表格文档宽度一致。
- 列宽按内容长度加权分配（中文=2 单位、西文=1），**表头行权重 ×2**——保证标题单元格单行显示。
- 行高自动适应内容（微软官方机制）。

### 5.3 表单类列宽

表单类表格（如文件信息表：文档编号/分类/版本/… | 值）遵循**档位制**：

- **标签列 = 内容档位宽**：能容纳该列最长标签的宽度 + 单元格边距 + 少量呼吸富余，全表统一一个档位，不随行内容变化。
- **剩余宽度全部给值列**：值域空间充裕，长值单行可放。
- 依据：SAP Fiori label-field ratio（2:10 / 4:8 栅格档位）、ANU 官方指南（label 默认 20% 档位）、语雀规范（label 80/120px 档位，同容器统一 label 宽度）。

判断公式：标签列宽 = max(标签列内容需求宽度) + 边距（226 twips）+ 呼吸富余（约 150 twips）。

### 5.4 单元格边距

上下 0.1cm（57 twips）+ 左右 0.2cm（113 twips）——对齐企业模板"内边距 0.1-0.3cm"与论文规范"上下 0.1cm、左右 0.2cm"。

### 5.5 表头与跨页

- 表头**单行显示**：表头文字保持简短（微软"brief, ideally one line"）+ 列宽保证。
- 跨页**表头重复**（tblHeader）：长表每页顶部自动重复表头。
- **防断行**（cantSplit）：单行内容不被拆到两页。
- 内容过长**允许折行**，不强制 nowrap 硬扛（WCAG 可访问性兜底）。

### 5.6 L3 SOP 审批信息表

- **L3 SOP**：在 `## 审批信息` 标题下写审批表（编制人/审核人/批准人/生效日期），生成器会将其并入首页文件信息表，不单独成表。
- **L1/L2 规范与说明文档**：**不写审批表**——审批信息由 front matter 的 `author`（编制人）/ `approver`（批准人）/ `effective_date`（生效日期）承载。
- **禁止裸写**：不要在标题下直接放置无 `## 审批信息` 标题的审批表——无标题表格会被渲染为普通数据表（首行作表头），产生冗余独立表。

## 6 自查清单

新增或修改任何表格时，逐项核对：

- [ ] 表头行：居中 + 加粗 + 浅灰底纹（E6E6E6）？
- [ ] 行标签列（第一列）居中？
- [ ] 数据列按类型对齐：文本左 / 数值右 / 短标签·日期·版本居中？
- [ ] 列内无混排（列级统一）？
- [ ] 所有单元格垂直居中？
- [ ] 表格铺满页宽，列宽按内容加权，表头单行？
- [ ] 表单类标签列用档位宽度，剩余给值列？
- [ ] 单元格边距 0.1/0.2cm？
- [ ] 跨页表头重复 + 防断行？
- [ ] 审批信息表仅在 L3 SOP 存在（且带 `## 审批信息` 标题），L1/L2 无审批表？
